# RFC 0017: Languages and regions

- **Status:** Accepted
- **Author:** Mateusz Pianka
- **Created:** 2026-10-05
- **Last changed:** 2026-10-05
- **Supersedes / superseded by:** —

## Summary

Text is translated with gettext, its English wording serving as the id;
dates, numbers and plurals follow the region, from Unicode's locale data.
The owner picks languages in order of preference, with English last, and
a region apart. The firmware comes in English; other languages are
packages from the store, installed on internal flash, so they work without
a memory card.

## Problem

- [RFC 0008](0008-runtime.md) makes every text in a manifest a message
  id, translated by catalogues inside the package, in the format of this
  RFC ("gettext is the likely one").
- [RFC 0009](0009-packages.md) takes what a permission allows from the
  system's catalogue, so an app cannot change how it reads, and only the
  app's reason from the app's.
- NuttX's C library has gettext, compatible with GNU's: it reads compiled
  `.mo` catalogues, plural rules included, from a path that can be set. It
  also has iconv, for converting between character encodings.

## Proposal

### Catalogues

Text is translated with **gettext**:

- **Translators edit `.po` files,** with the usual tools (Poedit,
  Weblate); the build compiles them into `.mo` files, which the device
  reads.
- **The English text is the id,** as gettext normally works, with a
  context added where one English word has two meanings. Manifests too
  hold English text, translated by the package's catalogues; if a
  translation is missing, the English shows, never an id.
- **Plural rules** travel in each catalogue's header, as in gettext.

| Catalogues of | Live in |
|---|---|
| the system: the system UI, services, permissions' meanings | `/usr/share/locale/<language>/LC_MESSAGES/`, in the firmware ([RFC 0010](0010-file-layout.md)) |
| a built-in or installed app | its package |
| a language pack | its package (below) |

NuttX's catalogue path is set to `/usr/share/locale`.

### Apps' translations

The runtime looks up a WebAssembly app's texts in that app's own
catalogues, when the app asks it to translate one, so apps carry no
gettext code. A change of language reaches running apps as an event, and
they show their texts again.

### Language and region

- **Languages:** the owner picks languages in order of preference; each
  text comes in the first of them that has it, and English is always the
  last.
- **The region** is chosen apart, as Android's regional preferences are:
  how dates and times are written, 12 or 24 hours, the first day of the
  week, units.
- **Changing either** takes effect at once: the system UI and running apps
  show their texts and formats again, as they do for a change of theme.

### Formats

Dates, times, numbers and plural rules come from **CLDR**, Unicode's
locale data. The build trims it to small tables for each language and
region, kept with the catalogues.

### Languages that ship, and language packs

- **In the firmware:** English only.
- **Every other language is a language pack:** a package from the
  project's repository (RFC 0009), holding catalogues and format tables,
  which the owner downloads from the store. They are installed in
  the package store, on internal flash and read-only, not on the apps'
  storage: a language pack has no data of its own, so it works without a
  memory card and before the first unlock, like English in the firmware.

### Scripts

- **Now:** Latin, Cyrillic and Greek.
- **Later, with the system UI:** right-to-left scripts, such as Arabic and
  Hebrew, and Chinese, Japanese and Korean. They need large fonts and
  changes to how screens are laid out.

Fonts, keyboard layouts and typing letters with diacritics are designed
with the system UI.

## Alternatives

- **ICU MessageFormat, or Android-style XML files.** Richer (genders,
  choices), but heavier, and not in NuttX.
- **A format of the project's own.** No outside tools would edit it.
- **Symbolic ids,** such as `perm-lora-reason`. Stable when the English
  changes, but a missing translation shows the id, and developers write
  every text twice.
- **gettext inside each app.** No runtime function, but every app would
  carry the code and read its own catalogues.
- **Language packs on the apps' storage,** like installed apps. Room on
  the memory card, but the device would lose its language without a card,
  and before the first unlock.

## Costs and risks

- **English as the id:** changing an English text breaks its translations
  until they are updated.
- **Translations need translators;** a language pack ships only what has
  been translated, and shows English for the rest.
- **CLDR's tables** take room for every language and region shipped; to be
  measured.
- **Scripts beyond Latin, Cyrillic and Greek** wait for the system UI's
  fonts and layout.
